# PrivatB — прототип мобильного банка (PWA)

Фронтенд-прототип мобильного банковского приложения: биометрический вход, дашборд,
операции по карте, генерация PDF-выписки, локализация UA/EN, тёмная тема и офлайн-режим.
Серверной части нет — все данные статические.

## Запуск

Service worker и установка PWA требуют `http://localhost` или HTTPS — через `file://`
приложение откроется, но офлайн-кеш и установка на устройство работать не будут.

```bash
python3 -m http.server 4173
```

Затем откройте <http://localhost:4173>.

В Claude Code этот же сервер поднимается конфигурацией `.claude/launch.json` (имя `privatb`).

## Вход по биометрии

[js/biometrics.js](js/biometrics.js) использует WebAuthn, поэтому вызывается
настоящий системный аутентификатор: Touch ID или Face ID на устройствах Apple,
Windows Hello, отпечаток на Android. Первый вход создаёт платформенный credential
(`navigator.credentials.create`), последующие подтверждают его
(`navigator.credentials.get`) — оба вызова показывают системный запрос.

Идентификатор credential'а хранится в `localStorage` под ключом
`privatb.credential`. Сбросить привязку — «Ще» → «Безпека».

Ограничения:

- Нужен защищённый контекст: HTTPS или `localhost`. По `file://` и по адресу
  в локальной сети биометрия недоступна.
- Сервера нет, поэтому подпись аутентификатора ни с чем не сверяется —
  приложение доверяет самому факту успешной проверки пользователя системой.
  В настоящем банке assertion уходил бы на бэкенд для валидации.
- Если платформенного аутентификатора на устройстве нет, приложение честно
  сообщает об этом тостом и показывает демонстрационную анимацию сканирования.

## Быстрые действия

У каждого своя логика, [js/modules.js](js/modules.js) (кроме QR — он в `app.js`).

**Переказ** — форма перевода: карта получателя с маской 4-4-4-4, сумма с быстрым
выбором (100/200/500/1000), комментарий. Валидация: 16 цифр, не своя карта, сумма
больше нуля и в пределах баланса. Дальше шаг подтверждения с комиссией (0,5%,
минимум 5 ₴) и итогом к списанию, затем обработка и квитанция.

**Поповнити** — реквизиты для входящего платежа: получатель, IBAN, номер карты,
назначение. Каждое поле копируется отдельной кнопкой, есть «Скопіювати все» и
«Поділитися» через Web Share API, где он поддерживается.

**Платежі** — каталог: категория → поставщик → форма. Для мобильной связи поле
телефона с маской `0XX XXX XX XX`, для остальных — лицевой счёт. Дальше подтверждение,
обработка и квитанция.

**QR-оплата** — единственный модуль с камерой: полноэкранный видоискатель через
`getUserMedia` с задней камерой, рамка с уголками и бегущая полоса. Распознавания нет.
Поток гасится при закрытии, уходе в фон и выходе из аккаунта; отказ в доступе
показывается карточкой с кнопкой повтора. Нужен HTTPS или `localhost`.

Баланс карты остаётся статичным — переводы и платежи его не меняют, как и задумано
в исходном ТЗ. Флоу доводится до квитанции, но состояние счёта не мутирует.

## Реквизиты карты

Кнопка-глаз на карте и действие «Реквізити» раскрывают полный номер, срок и CVV.
Номер начинается с `9720` — этот диапазон не выдаёт ни одна платёжная система,
поэтому он не может совпасть с настоящей картой. По тапу номер копируется в буфер.
Реквизиты автоматически скрываются через 20 секунд.

## Защита от случайного выхода

Навигация зеркалится в `history`, поэтому системный жест «назад» (свайп от края на iOS,
кнопка «Назад» на Android) двигается внутри приложения. В запасе всегда одна запись
истории: последний «назад» перехватывается и показывает подтверждение «Вийти із
застосунку?». Закрытие вкладки дополнительно перехватывается через `beforeunload`.

Полностью закрыть себя веб-приложение не может — это решает ОС или браузер.
Кнопка «Вийти» пробует `window.close()` и, если окно открыто не скриптом,
честно просит закрыть приложение вручную.

## PDF-выписка

`Statement.generate({ from, to })` — ISO-даты включительно; возвращает Promise и
скачивает файл. Периоды: последняя неделя, последний месяц, произвольный диапазон
(с валидацией: обе даты заданы, `from ≤ to`, `to` не в будущем).

Документ содержит шапку с реквизитами, блок клиента и счёта, полосу итогов,
таблицу «Дата / Опис операції / Сума / Валюта», итоговый блок с входящим и исходящим
остатком, постраничные колонтитулы и разбивку на страницы с повтором заголовка таблицы.

Кириллица в PDF работает за счёт встроенного сабсета PT Sans (SIL OFL 1.1) — jsPDF
со стандартными шрифтами кириллицу не отображает. Сабсет содержит Latin, кириллицу,
пунктуацию и знак гривны `₴`.

Реквизиты банка в шапке (МФО, ЄДРПОУ, адрес, телефон) — условные и намеренно
не совпадают ни с одним действующим банком.

### Пометка «демо»

Выписка по вёрстке повторяет реальный банковский документ, поэтому каждая страница
несёт водяной знак «ЗРАЗОК» / «SPECIMEN» и строку в колонтитуле. Пометка не влияет
ни на один экран приложения. Настройки — константа `DEMO_MARK` в начале
[js/statement.js](js/statement.js).

## Баланс и данные

Клиент — Ковальчук Анастасія Ігорівна. Баланс карты статичен: **511 000,00 ₴**.
Операции хранятся от новых к старым без
остатков — остаток после каждой операции вычисляется обратным ходом от 511 000,00,
поэтому самая свежая операция всегда оставляет счёт ровно на этой сумме. Входящий
остаток за любой период выводится из того же ряда.

История: 82 операции с 05.02.2026 по 02.08.2026. «Сегодня» для прототипа зафиксировано
в `DATA.today = '2026-08-02'`, чтобы относительные периоды совпадали с данными.

Суммы форматируются с пробелом-разделителем тысяч и запятой перед копейками
(`511 000,00 ₴`) в обоих языках.

## Локализация

Язык переключается кнопкой UA/EN (шапка, экран входа, раздел «Ще») и сохраняется в
`localStorage` под ключом `privatb.lang`. Тема — `privatb.theme`.
Статические строки помечены `data-i18n`, динамические рендерятся через `t(key, params)`.

## Обновление кеша

При изменении любого файла из `PRECACHE` поднимите версию в `sw.js`:

```js
var CACHE = 'privatb-v2';
```

Иначе браузер продолжит отдавать старую версию из кеша.
